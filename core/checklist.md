# 精读交付验收

与 `paper-flow show spec` 配套使用；核验原文，不以笔记自己的“已核查”声明作证。

- [ ] 标题可检索，开头说明研究矛盾与用途；中文为主，必要英文术语保留。
- [ ] 新笔记按正式模板十段组织；旧笔记保留原有组织。
- [ ] Citation、版本、DOI（可核实才写）、实际材料来源和解析路线可追溯；不从附件 key 猜父条目链接。
- [ ] `status`、`project`、`created` 与实际情况一致；项目未知可留空，不编造。
- [ ] Citation 后有核心价值看板、阅读范围与状态依据。
- [ ] 任务、真正困难、假设、方法信息流、核心结果、局限、创新切入点和研究用途均有实质回应或明确材料缺口。
- [ ] §4 保留设置、Baseline、指标、实测值、单位及必要分母；§5 审查支撑程度、条件和外推。
- [ ] 核心结论和方法点逐项回查来源；解析损坏或未找到的材料仍列待核查，未被当作不适用。
- [ ] 系统/框架/数据集论文的损失、指标、控制律或标定目标已核查。
- [ ] 图注给出出处，读者知道去哪里看、比较什么、能得出什么结论。相邻实验的条件和指标清楚。公式有来源、符号/单位、直觉、含义和成立条件。
- [ ] 正文已解释的图/公式在速查节仅作定位；确无须摘录时说明核查范围与理由。
- [ ] 已区分拟合/独立测试、频率/带宽、测量/估计/真值、训练/部署信息；“提升”有可比较证据。
- [ ] 作者原意与 **【笔记推断】** 清楚区分；§8 的每条创新点绑定具体短板及可验证的新机制，§9 关联已知课题，§10 给出定性裁定。
- [ ] 图片真实存在于笔记相对 `assets/<paper-slug>/`；没有缓存绝对路径、断链、空双链、未填占位符或不配对公式。
- [ ] 关键参数与结论便于扫读，正文保留理解论文所需的信息，解析和写回日志留在执行记录里。
- [ ] 如有 PDF 批注，逐条打开确认划线原句能支撑弹出评论，独立结果各自定位，评论说明这句话对理解论文的作用。回看整篇的批注分布，给尚未解释的关键设计选择、实验条件或适用边界补上原句。
- [ ] 关键证据缺口保留 `in-progress`；`done` 对应明确范围内的证据闭环，非关键待办已解释影响。
- [ ] 人工索引已登记有效双链和导读，或固定“待补收录”有待办；如无法持久化，交付明确未写入记录及原因。
- [ ] 只修改任务相关资料，保留旧入口、历史笔记结构、人工批注、绘图内部数据及项目设置。

若另交付或条件触发一图流：确认满足触发条件（显式要求，或 `usefulness: 高`、`status: done` 且具清晰方法/系统因果链）；实际渲染且检查单页 16:9、无溢出遮挡缺字、960×540 可读；自动触发或要求融入笔记时，“文献一图流速览” Callout 位于看板与阅读范围之后且相对路径可解析；数字及箭头可追溯；源码与资产可迁移；未核查证据在图上可见，原笔记状态保持真实。若渲染失败，交付明确为源码草稿。

若执行 PDF 写回：整批引文预检、页码基准、完整匹配和歧义检查通过；稳定 ID 去重，只更新引擎批注；保留手工批注；当轮备份、临时文件重开验证、源文件变化检查和原子替换均成功。分别记下预检结果、备份路径和实际写入数。
