# 文献精读规范 v3.2

本规范定义内容、证据和完成条件；`paper-flow show note-template` 提供新笔记布局（首屏看板 + 五段渐进主干）。历史笔记沿用原有标题、组织，按概念核查，不追溯重写正文。Vault 自身的项目指令仍负责输出目录、专题别名和人工索引位置。

## 写给谁

**工作流面向 Agent，笔记和批注面向读者。** 正文按**人类建立认知的渐进顺序**组织（破冰场景 → 概念搭桥 → 单帧走查与直觉 → 公式与实证钩子 → 边界与迁移），不把后台核查清单生硬倒扣在读者头上。

**工具层勘误静默消化法则**：凡是解析工具（MinerU / OCR）导致的错行、合并表格、漏符号或排版偏差，以及文件 SHA-256 指纹、缓存任务号、本地路径和原文中“上下文无歧义且不影响推导/代码”的纯文字笔误，AI 回查原 PDF 确认正确内容后**静默修好、直接写对**，严禁在笔记正文中写“修复了 MinerU 错位”或“修正 OCR 识别”等后台过程日志。**只有 3 类真问题必须显式预警**：
1. 照着原论文公式敲代码会算错/报错的数学或维度硬伤；
2. 原论文前后章节自相矛盾（影响复现接口或数值成立性）；
3. 具有误导性的统计口径暗门（如分步积分充当成功率、控制频率充当带宽）或原 PDF 本身缺失模糊处。

图注先点出这张图回答的问题，再告诉读者看哪一栏、哪条线或哪个阶段，以及从那里可以得出什么结论。相邻图比较不同因素时，交代各自改变了什么、哪些条件相同。有符号的曲线读数和按幅值报告的峰值要说清楚。试验成功次数保留分母和场景，演示结果只说明观察到的能力。

PDF 下划线选中能独立支撑评论的原句。弹出评论说明这句话为什么值得划，必要时指向对应图表，写明比较条件或关键限制。峰值力、成功次数等结论若由不同原句支持，分别划线并各写一条评论。预检时核对每条评论对应的引文、物理页与栏位。

## 1. 必备内容与渐进结构

正式精读采用 **首屏看板 + 五段渐进主干**：
- **首屏区**：`Citation`、`> [!NOTE] 核心启发与复用价值（30 秒决策看板）`（`本质创新` 控制在 100 字内零黑话，含复用点、硬伤与**定性裁定+分层阅读路线**）、`> [!INFO]- 阅读范围与状态依据`（默认折叠）及 `一句话`（零缩写人话破题）。
- **§1 问题、困境与切入点**：物理场景输入/输出/指标 → 底层死锁与前人对比（合一讲顺 Research Gap）→ 成立假设 → 按需 `> [!TIP] 读前 1 分钟概念桥`（跨领域论文必加）。不在 §1 提前抛入 §2 才定义的内部符号。
- **§2 核心方法：从直觉到机制**：`§2.1` 用**单样本具象走查**（真实维度/单周期）串起全局与离线/在线分工；各子模块按「不做会怎样 → 核心直觉与机制 → 关键公式 → 实证钩子」四步展开，繁琐标定细节放 `> [!DETAILS]-` 折叠块。
- **§3 实验证据与论证审视**：合并原实验台账与论证检视。每节以「一句话看懂本组实验」开头，客观记录设置、Baseline、实测值与分母，并在同节当场审视对比公平性、统计口径与外推边界。不设单独重复的 Claim 大表，也不设空壳图式速查节。
- **§4 失效边界与破局思路**：区分原文承认的局限与阅读者推断，再按“具体短板 X + 新机制/异构条件 Y → 可验证创新点 Z”构造破立闭环。
- **§5 课题迁移与行动项**：直接可拆走模块、实操避坑红线、My Take 衔接、可执行 Action Items 与 `Related Notes`（严禁生成库内不存在的空双链或把 `zotero://` 放进 `[[...]]`）。

材料不足时写明缺口及受影响结论。研究背景未知时写“潜在关联，待确认”，不替用户编造需求。

## 2. 受控元数据规范

- **YAML 引号保护**：`title`、`authors`、`publication`、`doi`、`project` 等字符串字段统一加双引号，防止冒号 `:` 破坏 YAML 解析。
- **精简分类字段**：移除冗余的 `topic` 与 `keywords`。
- **`project`（6 选 1 纵向桶）**：`触觉抓取与力控`、`触觉感知与表征`、`接触丰富操作学习`、`仿真、基准与Sim2Real`、`机器人控制与机构`、`综述与领域地图`。
- **`tags`（封顶 2–3 个正交横向标签）**：严禁使用 `paper`、`literature-note` 等目录废话词或单篇专有模型名，仅从以下受控词表选取：
  - 硬件/传感：`visuo-tactile`、`magnetic-tactile`、`piezoresistive`、`intrinsic-sensing`、`parallel-gripper`、`dexterous-hand`、`bimanual`
  - 方法范式：`model-based-control`、`reinforcement-learning`、`imitation-learning`、`self-supervised`、`differentiable-sim`、`sim-to-real`
  - 任务/体裁：`slip-control`、`friction-stiffness`、`in-hand-manipulation`、`precision-assembly`、`survey`
- **Zotero 链接核验**：确认父条目 key 与附件 key 后才写 `zotero_link` / `pdf_link`，不得留截断前缀，不得把父 key 填入 `pdf_link`。

## 3. 证据逐项核查

从核心方法和主要结论建立核查意识，每项在正文或 §3 论证审视中定位至原文图、表、公式、定理、章节或物理页，并保留成立条件：

| 类型 | 记录义务 |
| --- | --- |
| 已核查 | 具体来源确实支持当前措辞；记录出处、必要解释和条件。 |
| 待核查 | 写明原文缺失、不可辨认或前后冲突的内容及受影响结论（原 PDF 看不清时才标待核查）。 |

系统、框架、数据集类论文也要显式检查损失函数、评价指标、控制律、标定关系或优化目标。定量结论保留指标、单位、设置、基线及比较范围；区分拟合与独立测试、更新率与带宽、估计与真值、单指力与总力、训练信号与部署信号。

关键数字、表格、公式和方法歧义回查原 PDF；摘要、元数据或批注不能代替未读取的全文。

## 4. 事实与推断

区分原文事实、作者主张、作者承认的局限、待核查问题与阅读者分析。AI 或个人分析、猜测、疑问及补充意见统一用 **【笔记推断】** 或 `> [!NOTE] 笔记推断` 标注，不冒充作者结论或用户既定判断。

## 5. 阅读范围与完成状态

新建精读默认 `status: in-progress`。影响核心方法复现或主要结论的关键证据缺口未关闭时保持该状态。只有在明确限定范围内核心证据核实闭环、假设和局限清楚时使用 `status: done`。影响“从头复训/完整重现”但不影响“理解机制与直接调用模块/权重”的未公开细节，集中写入首屏折叠状态依据即可，不重复刷屏。

快速导入草稿使用 `unread`；空模板、摘要整理、成功解析及已生成一图流均不触发完成状态。当用户显式要求一图流，或精读完成复核且同时满足 `usefulness` 为 `高`、`status` 为 `done`、并具备清晰方法或系统因果链时，随精读生成一图流并自动嵌入首屏。正文完成与索引完成分别报告。

完成后在配置的人工检索入口或二级专题登记有效双链与导读；未确认文献放固定“待补收录”追踪表。`paper-flow index` 重建自动台账；传入 `--note` 时另行报告该笔记的人工入口登记结果。

## 6. 长期资产与排版

关键图片复制至笔记同级 `assets/<paper-slug>/`，采用 `![图片说明](assets/<paper-slug>/figX.jpg)`（目录与文件名禁止含空格）。需要宽度时可用 Obsidian 嵌入；历史格式无需批量转换。长期链接不依赖 Zotero 缓存、绝对设备路径（如 `C:\Users\...`）或临时下载。核心公式前给一句形象的物理/几何直觉，LaTeX 配对正确。关键参数与结论加粗，用客观工程学术语言。

## 7. 边界

引擎提供规范与入口分发、附件寻址、按需 MinerU 解析、笔记索引和可恢复的 PDF 写回。以 parse 返回的原 PDF 和经校验的全文作为材料，在重要结论处回查原文。PDF 内嵌下划线评论与 Zotero 数据库原生批注是不同功能。
