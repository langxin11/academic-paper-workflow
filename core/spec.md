# 文献精读规范 v3.1

本规范定义内容、证据和完成条件；`paper-flow show note-template` 提供新笔记布局。历史笔记沿用原有标题、组织与元数据，按概念核查，不追溯重排。Vault 自身的项目指令仍负责输出目录、专题别名和人工索引位置。

## 写给谁

**工作流面向 Agent，笔记和批注面向读者。** 正文从读者想弄懂的问题写起，讲清作者发现了什么、证据在哪里、在什么条件下成立。材料版本、出处及影响理解的缺口随文保留。文件指纹、解析任务号、重试和写回日志放在引擎的执行记录中。

图注先点出这张图回答的问题，再告诉读者看哪一栏、哪条线或哪个阶段，以及从那里可以得出什么结论。相邻图比较不同因素时，交代各自改变了什么、哪些条件相同。有符号的曲线读数和按幅值报告的峰值要说清楚。试验成功次数保留分母和场景，演示结果只说明观察到的能力。

PDF 下划线选中能独立支撑评论的原句。弹出评论说明这句话为什么值得划，必要时指向对应图表，写明比较条件或关键限制。峰值力、成功次数等结论若由不同原句支持，分别划线并各写一条评论。预检时核对每条评论对应的引文、物理页与栏位。

读者希望 PDF 里有较丰富的关键标注。准备批注时通读方法、结果和讨论，沿着读者复盘论文的顺序选原句：为什么这样设计，关键假设或公式怎样起作用，实验改变了什么，哪个结果支持结论，结论在哪些条件下可能失效。遇到直接影响解释的单位、分母、采样方式、近似或计算预算，就在相应原句旁写清它的意义。篇幅和证据决定条数；每增加一处，都应给读者一个已有批注尚未回答的问题。

## 1. 必备内容

正式精读采用十段式：问题、背景与 Research Gap、核心方法、关键实验与数据台账、Claim ↔ Evidence、图片速查、公式速查、局限与潜在创新切入点、研究用途、最终评价。另保留 Citation、一句话和 Related Notes。

每篇必须实质回应：可追溯文献信息；任务、真正困难与核心假设；方法机制及模块关系；主要结果与证据；客观局限及痛点绑定的创新切入点；研究用途。材料不足时写明缺口及受影响结论。研究背景未知时写“潜在关联，待确认”，不替用户编造需求。

一句话导读说明“针对何种矛盾 + 核心机制 + 关键量化表现（如有）+ 核心启发或代价”，不凑固定句数，不制造指标。

## 2. 章节分工

- **§4 数据台账**：客观记录测试条件、对象、Baseline、指标、实测值、消融、鲁棒性及失败案例。理论、定性、系统或资源论文按实际成果记录命题、假设、证明思路或产物与评价范围，不补造实验。
- **§5 论证检视**：逐项对照 Claim 与原文证据，检查支持程度、隐藏前提和外推边界。数字重复不是论证闭环。
- **§8 破立闭环**：区分作者承认的局限与阅读者推断。先解释客观物理/技术天花板及失效边界，再按“具体短板 X + 新机制/异构条件 Y → 可验证创新点 Z”提出思路，附验证方向；避免无技术锚点的泛泛建议。
- **§9 迁移**：与已知课题或工程项目连接，说明可复用设计、算法、建模、避坑和后续动作。
- **§10 裁定**：简洁判断本质创新、核心 Trick、存疑点和跟踪建议。
- **§6/§7 速查**：正文已详解的图/公式仅保留单行定位；未详解的关键项在速查节补全解析。

## 3. 证据逐项核查

从核心方法和主要结论建立短证据清单，可直接放在 Claim ↔ Evidence 中；每项定位至图、表、公式、定理、章节或 PDF 物理页，并保留成立条件。

| 类型 | 记录义务 |
| --- | --- |
| 已核查 | 具体来源确实支持当前措辞；记录出处、必要解释和条件。 |
| 不适用 / 无需摘录 | 写明实际核查范围及理由；正文已完整解释者指向该处。 |
| 待核查 | 写明缺失材料、已知线索和影响的结论。解析缺失、无法辨认、检索未命中均属于此类。 |

核查一个证据不代表其余证据已核查。系统、框架、数据集类论文也要显式检查损失函数、评价指标、控制律、标定关系或优化目标。确无须摘录图或公式时，分别交代核查范围和结论；不设摘图、摘式数量要求。

定量结论保留指标、单位、设置、基线及比较范围；涉及提升时保留原始值与分母（原文提供时）。区分拟合与独立测试、更新率与带宽、估计与真值、单指力与总力、训练信号与部署信号。理论结果仅整理原文命题、假设及证明思路。

关键数字、表格、公式和方法歧义回查原 PDF；MinerU 解析是阅读辅助，解析成功不等于证据已核实。摘要、元数据或批注不能代替未读取的全文。

## 4. 事实与推断

区分原文事实、作者主张、作者承认的局限、待核查问题与阅读者分析。AI 或个人分析、猜测、疑问及补充意见统一用 **【笔记推断】** 或 `> [!NOTE] 笔记推断` 标注，不冒充作者结论或用户既定判断。

## 5. 阅读范围与完成状态

新建精读默认 `status: in-progress`。影响核心方法复现或主要结论的关键证据缺口未关闭时保持该状态。只有在明确限定范围内核心证据核实闭环、假设和局限清楚时使用 `status: done`。保留的非关键待办说明为何不影响主要结论。用户限定范围时，`done` 仅表示该范围内完成。

快速导入草稿使用 `unread`；空模板、摘要整理、成功解析及已生成一图流均不触发完成状态。当用户显式要求一图流，或精读完成复核且同时满足 `usefulness` 为 `高`、`status` 为 `done`、并具备清晰方法或系统因果链时，随精读生成一图流并自动嵌入首屏（也可由目标 Vault 本地规约进一步补充条件）。正文完成与索引完成分别报告。

完成后在配置的人工检索入口或二级专题登记有效双链与导读；未确认文献放固定“待补收录”追踪表。索引写入失败不阻塞当前正文；如追踪表也无法写入，在交付中列出未持久化的链接、待办及原因。`paper-flow index` 重建自动台账；传入 `--note` 时另行报告该笔记的人工入口登记结果。

## 6. 长期资产与排版

关键图片复制至笔记同级 `assets/<paper-slug>/`，采用 `![图片说明](assets/<paper-slug>/figX.jpg)`。需要宽度时可用 Obsidian 嵌入；历史格式无需批量转换。长期链接不依赖 Zotero 缓存、绝对设备路径或临时下载。图必须说明原文位置、阅读要点及对应结论；公式必须说明出处、符号、适用单位、意义及成立条件，LaTeX 配对正确。

Citation 后配置 `> [!NOTE] 核心启发与复用价值`，提炼本质创新、可复用点、核心硬伤和阅读建议；用 `> [!INFO]` 单列阅读范围与状态依据。核心公式前给一句形象的物理/几何直觉。关键参数与结论加粗，用客观工程学术语言。

## 7. 边界

引擎提供规范与入口分发、附件寻址、按需 MinerU 解析、笔记索引和可恢复的 PDF 写回。以 parse 返回的原 PDF 和经校验的全文作为材料，在重要结论处回查原文。PDF 内嵌下划线评论与 Zotero 数据库原生批注是不同功能。
