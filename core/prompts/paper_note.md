# 中文文献精读任务（v3.2）

读取 `paper-flow show spec`、`paper-flow show note-template` 和 `paper-flow show checklist` 后执行本流程。命令入口与本机配置见项目 README 及当前技能入口。规范定义证据与状态，模板定义五段渐进布局，目标 Vault 的项目指令定义目录和人工索引；历史笔记保持原组织。

## 1. 确认材料与范围

用户只说“精读《论文标题》”时，直接调用 `paper-flow parse --title "<论文标题>" --cloud --json`。调用者指定离线时用 `--local-only`。先确认唯一文献和唯一 PDF；重名、多版本或只能近似匹配时，列出候选请用户选，确认前先停下。拿到已指定的 PDF、Zotero 附件 key 或本地解析材料时直接从该材料开始。用标题、作者、DOI 核对论文版本；附件 key 与父条目 key 分开处理，不能凭附件 key 拼造父条目链接，也不把父 key 填入 `pdf_link`。

用题名查询结果的 `vault`、`notes_dir` 确定正式库和笔记目录。未配置目标库时使用已有 Vault 路径选择规则；仍未找到时询问目标 Vault。按 DOI、条目 key、题名和版本检查现有笔记、人工检索入口及相关专题“待补收录”，避免重复。

优先复用已确认对应的 `full.md`、图像与可用图注清单；缺失或歧义时读取原 PDF。解析材料只是辅助，凡遇到公式、表格或数字存疑必须回查原 PDF。确认原 PDF 内容后**直接写对，不在正文汇报 MinerU/OCR 修复过程、缓存文件名或 SHA-256 哈希**。

## 2. 核查要点

写作前识别核心机制与主要结论依赖的图、表、定义、公式、实验或论证、原文位置、成立条件及缺口，逐项回查原 PDF。显式检查损失、指标、标定优化目标及控制律，包括系统或数据集论文。图/公式按理解需要选取，不设数量目标。仅当原 PDF 本身存在数学/维度硬伤、前后矛盾、误导性统计口径暗门或模糊缺页时，才在笔记中显式标出预警或 `待核查`。

## 3. 撰写正式笔记（首屏看板 + 五段渐进主干）

遵循模板「首屏看板 + 五段渐进主干」。推荐文件名 `<FirstAuthor> et al. <Year> - <ShortTitle>.md`，输出目录以 Vault 配置/指令为准。元数据按以下受控规范填写：
- 字符串含冒号必须加双引号（`title`、`authors`、`publication`、`doi`、`project`）；
- 不写 `topic` 与 `keywords`；
- `project` 从 6 个固定桶选 1 个；
- `tags` 从 18 个受控正交词表选 2–3 个；
- 填写真实 `source`、`parse_route`、`status`（默认 `in-progress`）、`created`。

按读者认知动线撰写：
1. **首屏**：`Citation` 下放紧凑的 30 秒决策看板（`本质创新` 限 100 字内零黑话，含定性裁定与分层阅读路线），`> [!INFO]-` 默认折叠阅读范围与状态依据；`一句话` 用大白话破题。
2. **§1 问题、困境与切入点**：物理场景讲清输入输出（不提前抛 §2 内部符号）→ 底层死锁与前人对比表合一 → 核心假设 → 跨领域论文按需加 `> [!TIP] 读前 1 分钟概念桥`。
3. **§2 核心方法**：`§2.1` 写单样本具象走查（用真实维度串起全链路与离线/在线分工）；各子模块按「不做会怎样 → 核心直觉与机制 → 关键公式（公式前给物理/几何直觉）→ 实证钩子」四步展开；繁琐型号参数放 `> [!DETAILS]-` 折叠。
4. **§3 实验证据与论证审视**：合并事实台账与论证检视。每节开头一句“一句话看懂本组实验”，紧跟数据表/图并在同节当场审视对比公平性、统计口径与外推边界（区分“原文 §X”与“本文 §X”）。
5. **§4 失效边界与破局思路** & **§5 课题迁移与行动项**：先客观边界再痛点绑定破局思路；直给可拆走模块、避坑红线与 Action Items。所有阅读者分析显式标注 **【笔记推断】**。`Related Notes` 仅引用 Vault 内已真实存在的笔记。

对照论文图号裁取或选用对应原图，检查分辨率、图例和坐标是否可读。图复制到笔记同级无空格路径 `assets/<paper-slug>/` 就近展示，保留图号、页码、阅读要点和对应结论。保证 MathJax 配对与折叠 Callout 每行 `>` 前缀完整。关键参数与结论加粗。

## 4. 复核与登记

逐条对照原文与 checklist，修正超出证据的措辞。关键方法或结论缺口未关闭就保持 `in-progress`；限定范围内核实闭环才设 `done`，非关键待办（如仅影响从头复训底座）集中在首屏折叠依据中说明。

在配置的人工索引或专题中登记有效双链与简洁导读，避免重复挂载。用 `paper-flow --vault "<Vault>" index --note "<笔记相对路径>" --guide "<导读>"` 同时登记并刷新台账；用 `index --check` 核对台账。正文与索引结果分别报告。

## 5. 按需与有条件附加交付

**一图流触发条件**：满足以下任一条件时，读取 `paper-flow show one-pager-prompt` 与 `paper-flow show one-pager-template` 制作一图流：
1. 用户显式要求一图流、单页速览或 graphical abstract；
2. 精读完成复核后同时满足：`usefulness` 为 `高`、`status` 为 `done`，且论文具备清晰的方法或系统因果链（纯理论证明、纯综述或关键证据未闭环时不自动触发）。

自动触发或用户要求嵌入时，将产物（`.typ`、`.svg`、`.png`、`one-pager-content.md` 及引用原图）保存至笔记同级 `assets/<paper-slug>/`，并在首屏阅读范围之后插入或更新“文献一图流速览” Callout；制图不自动更改精读状态。

普通精读只读取原 PDF。只有明确要求给 PDF 加批注或划线时，才按 `paper-flow show colors` 与 `paper-flow annotate --help` 执行预检与写回。

完成写入后逐项解析笔记中嵌图和索引中的双链，确认实际文件存在且图片可打开。返回已落盘笔记的可点击 Obsidian 链接（`obsidian://open?vault=…&file=…`），简述阅读范围、状态依据、主要缺口和索引结果。
