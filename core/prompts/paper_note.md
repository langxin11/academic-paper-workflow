# 中文文献精读任务

读取 `paper-flow show spec`、`paper-flow show note-template` 和 `paper-flow show checklist` 后执行本流程。命令入口与本机配置见项目 README 及当前技能入口。规范定义证据与状态，模板定义布局，目标 Vault 的项目指令定义目录和人工索引；历史笔记保持原组织。

## 1. 确认材料与范围

从用户给定 PDF、可访问的 Zotero 附件或本地解析材料开始。用标题、作者、DOI 核对论文版本；附件 key 与父条目 key 分开处理。多个候选或链接附件有歧义时先列候选，不能凭 key 拼造条目链接。记录实际读取材料；不假设能访问用户未开放的库、全文或私人背景。

按目标 Vault 配置检查现有笔记、人工检索入口及相关专题“待补收录”，避免重复。可参考一两篇近似主题笔记的深度和语言，但不以历史布局替代正式模板。索引补录失败不阻塞本篇，交付报告未持久化事项。

优先复用已确认对应的 `full.md`、图像与可用图注清单；缺失或歧义时读取原 PDF。解析材料是辅助证据，不凭记忆补损坏的公式、表格或数字。首版 CLI 不提供自动定位、云解析或下载；使用现有可访问材料及 Agent 文件工具。外部服务使用遵循用户授权和本机策略。

## 2. 建立证据清单

逐项列出核心机制和主要结论依赖的图、表、定义、公式、实验或论证、原文位置、成立条件及缺口；可直接使用 Claim ↔ Evidence 区，不另堆流程表。图表和核心公式/数字回查 PDF。分类为已核查、不适用/无需重复摘录（范围及理由）、待核查（材料及影响）。不以单项成功清除其他缺口。

显式检查损失、指标、标定优化目标及控制律，包括系统或数据集论文。图/公式按理解需要选取，不设数量目标。定量、理论、定性/系统结果按实际内容并存；理论证明只概括原文提供的思路。

## 3. 撰写正式笔记

遵循模板十段式。推荐文件名 `<FirstAuthor> et al. <Year> - <ShortTitle>.md`，输出目录以 Vault 配置/指令为准。元数据填写真实 `source`、`parse_route`、`status`、`project`、`created`；默认 `in-progress`。

Citation 下放核心启发看板及阅读范围。导读抓住矛盾、机制、表现和代价。方法讲明信息流、训练/标定与在线部署的区别。相关工作用于解释贡献和基线，一篇关键前作也值得比较。

§4 记客观台账；§5 审查论证充分性；§8 先说客观局限，再按“具体短板 + 新机制/异构条件 → 可验证创新点”构造破立闭环；§9 连接已知课题或写“潜在关联，待确认”；§10 作裁定。所有阅读者分析显式标注 **【笔记推断】**。

图在解释方法或结果处就近展示：复制到笔记同级 `assets/<paper-slug>/`，保留图号、页码、阅读要点和支持结论。公式前给一句物理/几何直觉，解释必要符号、单位、意义和条件，保证 MathJax 配对。正文已解析项在速查节仅给单行定位。关键参数与结论加粗。

## 4. 复核与登记

逐条对照原文与 checklist，修正超出证据的措辞。关键方法或结论缺口未关闭就保持 `in-progress`；限定范围内核实闭环才设 `done`，非关键待办说明影响。

在配置的人工索引或专题中登记有效双链与简洁导读，标题或核心判断变化时更新原项。无法登记时进入固定“待补收录”；若该处也不能写，交付列出链接、动作及原因。正文与索引结果分别报告。自动台账为后续功能。

## 5. 按需附加交付

用户请求一图流时读取 `paper-flow show one-pager-prompt` 与 `paper-flow show one-pager-template`。制图不自动更改精读状态。

PDF 批注先读取 `paper-flow show colors`。首版仅定义语义及未来安全约定，不提供 `annotate` 命令，不调用不存在的脚本。用户要求写回而没有可靠工具时可交付批注计划并明确 PDF 未修改。未来工具须完整引文逐项预检、明确页码基准、拒绝歧义/前缀命中、稳定 ID 去重、保留手工批注、备份当轮原文件、临时副本重开验证、检查源文件未变后原子替换；这不同于 Zotero 原生数据库批注同步。

最终简述笔记与资产位置、阅读范围、状态依据、主要缺口和索引结果。仅完成源码/草稿时不声称成品已完成。
