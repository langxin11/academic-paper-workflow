# 中文文献精读任务

读取 `paper-flow show spec`、`paper-flow show note-template` 和 `paper-flow show checklist` 后执行本流程。命令入口与本机配置见项目 README 及当前技能入口。规范定义证据与状态，模板定义布局，目标 Vault 的项目指令定义目录和人工索引；历史笔记保持原组织。

## 1. 确认材料与范围

用户只说“精读《论文标题》”时，直接调用 `paper-flow parse --title "<论文标题>" --cloud --json`。调用者指定离线时用 `--local-only`。先确认唯一文献和唯一 PDF；重名、多版本或只能近似匹配时，列出候选请用户选，确认前先停下。拿到已指定的 PDF、Zotero 附件 key 或本地解析材料时直接从该材料开始。用标题、作者、DOI 核对论文版本；附件 key 与父条目 key 分开处理。多个候选或链接附件有歧义时先列候选，不能凭 key 拼造条目链接。记录实际读取材料；不假设能访问用户未开放的库、全文或私人背景。

用题名查询结果的 `vault`、`notes_dir` 确定正式库和笔记目录。未配置目标库时使用已有 Vault 路径选择规则；仍未找到时询问目标 Vault。按 DOI、条目 key、题名和版本检查现有笔记、人工检索入口及相关专题“待补收录”，避免重复。可参考一两篇近似主题笔记的深度和语言，但不以历史布局替代正式模板。索引补录失败不阻塞本篇，交付报告未持久化事项。

优先复用已确认对应的 `full.md`、图像与可用图注清单；缺失或歧义时读取原 PDF。解析材料是辅助证据，不凭记忆补损坏的公式、表格或数字。用 `paper-flow parse --attachment-key <附件key> --json` 或 `parse --pdf <PDF> --json` 获取材料路径。返回 `original-pdf` 时直接读原 PDF；`existing`、`cache` 或 `mineru-cloud` 返回经校验的全文路径，按实际阅读来源填写笔记。开启云解析后，退出码 3 表示本轮未完成，按提示用同一输入和参数续查。外部服务使用遵循用户授权和本机策略。

## 2. 建立证据清单

逐项列出核心机制和主要结论依赖的图、表、定义、公式、实验或论证、原文位置、成立条件及缺口；可直接使用 Claim ↔ Evidence 区，不另堆流程表。图表和核心公式/数字回查 PDF。分类为已核查、不适用/无需重复摘录（范围及理由）、待核查（材料及影响）。不以单项成功清除其他缺口。

显式检查损失、指标、标定优化目标及控制律，包括系统或数据集论文。图/公式按理解需要选取，不设数量目标。定量、理论、定性/系统结果按实际内容并存；理论证明只概括原文提供的思路。

## 3. 撰写正式笔记

遵循模板十段式。推荐文件名 `<FirstAuthor> et al. <Year> - <ShortTitle>.md`，输出目录以 Vault 配置/指令为准。元数据填写真实 `source`、`parse_route`、`status`、`project`、`created`；默认 `in-progress`。

Citation 下放核心启发看板及阅读范围。导读抓住矛盾、机制、表现和代价。方法讲明信息流、训练/标定与在线部署的区别。相关工作用于解释贡献和基线，一篇关键前作也值得比较。

§4 记客观台账；§5 审查论证充分性；§8 先说客观局限，再按“具体短板 + 新机制/异构条件 → 可验证创新点”构造破立闭环；§9 连接已知课题或写“潜在关联，待确认”；§10 作裁定。所有阅读者分析显式标注 **【笔记推断】**。

对照论文图号裁取或选用对应原图，检查分辨率、图例和坐标是否可读。图在解释方法或结果处就近展示：复制到笔记同级 `assets/<paper-slug>/`，保留图号、页码、阅读要点和支持结论。公式前给一句物理/几何直觉，解释必要符号、单位、意义和条件，保证 MathJax 配对。正文已解析项在速查节仅给单行定位。关键参数与结论加粗。

## 4. 复核与登记

逐条对照原文与 checklist，修正超出证据的措辞。关键方法或结论缺口未关闭就保持 `in-progress`；限定范围内核实闭环才设 `done`，非关键待办说明影响。

在配置的人工索引或专题中登记有效双链与简洁导读，标题或核心判断变化时更新原项。无法登记时进入固定“待补收录”；若该处也不能写，交付列出链接、动作及原因。正文与索引结果分别报告。用 `paper-flow --vault "<Vault>" index --note "<笔记相对路径>" --guide "<导读>"` 同时登记并刷新台账。已知材料缺口可用 `--backlog "<原因>"` 登记；用 `index --check` 核对台账。

## 5. 按需附加交付

用户请求一图流时读取 `paper-flow show one-pager-prompt` 与 `paper-flow show one-pager-template`。制图不自动更改精读状态。

普通精读只读取原 PDF。只有明确要求给 PDF 加批注或划线时，才执行下面的写回流程。PDF 批注先读取 `paper-flow show colors`。使用 UTF-8 JSON 对象指定 `page_base` 和 `annotations`；每条列出 `id`、`page`、`quote`、`color`、`comment`。用物理页序从 1 编号时设置 `page_base: 1`。对重复引文补充 `before` / `after` 或区域 `region`。先执行 `paper-flow annotate --pdf "<PDF>" --json "<计划>" --check`，核对整批命中页与范围，再去掉 `--check` 提交。记录备份路径，复跑检查同一 ID 是否零新增；写入 PDF 内嵌下划线与评论。

完成写入后逐项解析笔记中嵌图和索引中的双链，确认实际文件存在且图片可打开。返回已落盘笔记的可点击 Obsidian 链接（`obsidian://open?vault=…&file=…`，库名及库内相对路径分别做 URL 编码），简述阅读范围、状态依据、主要缺口和索引结果。仅完成源码/草稿时不声称成品已完成。

## 中文论述与信息取舍

先用直观语言说明问题、机制和适用条件，再展开公式。保留能影响方法选择或揭示失效边界的数据。写对照结果时，交代比较对象、测试条件、数值、单位和证据位置。写单次演示时，只说明在什么条件下观察到了什么。读者分析标注【笔记推断】，复现缺口写明它影响哪项结论或完成状态。

受托润色时，只提供已核查的目标段落，让写作助手返回逐段候选。人工逐项复核术语、因果关系、适用范围和证据位置后再采纳。数值与单位、引文、公式、表格、链接、YAML、状态及推断标记沿用原文。
